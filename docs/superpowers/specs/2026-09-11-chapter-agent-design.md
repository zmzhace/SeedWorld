# SeedWorld 流水线重构设计（v2：ainovel 骨架＋自有四样）

日期：2026-09-11 ｜ 状态：待评审 ｜ 版本：v2（替代 v1 章节 Agent 草案思路，收编其全部内容）
对应实现计划：待 `writing-plans` 产出

## 0. 背景与目标

线上数据实证的三类失败（2026-09-11）：

1. **卡死**：`WORKFLOW_MIGRATION_REQUIRED` 锁死且无法重规划；大纲三振出局锁整轮；
   `awaiting_chapter` 孤儿任务无恢复；前端按 latest 轮询跟错 run。
2. **全塞一起**：契约是验收清单，写手全写进去；节拍只有转合形状，无起承槽位。
3. **一直燃**：处处要高潮，无处能说“本章不许燃”。

另：工作台五步（档案/边界/推演/工坊/干预）按“阶段”切分，与按“轮次”转的真实工作错位；
手动编排与自动一轮一章是两条互不知晓的产章路径；`engine/orchestrator`＋12 系统与
`tick-workflow-service` 双驱动并存，哲学打架（涌现 vs 编剧）。

本设计以 ainovel-cli 流水线为骨架，保留我方四样差异化，一次解决上述问题。

## 1. 总架构：确定性 Engine＋Route＋Phase/Flow

```
┌──────────────────────────────────────────────────┐
│ Engine（确定性，零 LLM 开销）                      │
│ 读 Store → Route 决策表 → 派发 Worker → 循环       │
│ 启动选路 / 干预分诊 / 失败出路 → Arbiter 单次裁定   │
└──┬──────────┬──────────┬────────────┬────────────┘
   │          │          │            │
┌──▼───┐ ┌────▼───┐ ┌────▼────┐  ┌────▼────┐
│Archi-│ │Writer  │ │ Editor  │  │ Arbiter │
│tect  │ │(见§3)  │ │(弧评审) │  │(单次函数)│
└──┬───┘ └────┬───┘ └────┬────┘  └─────────┘
   └──────────┼──────────┘
              │ 工具调用（幂等＋checkpoint）
┌─────────────▼────────────────────────────────────┐
│ Store（SQLite 即事实层：ticks/runs/contracts/     │
│ beats/chapters/outlines/obligations/checkpoints） │
└──────────────────────────────────────────────────┘
```

- **调度零 LLM**：下一个派谁由 Route 决策表按 Store 事实推导，可穷举测试。内存 `Set`＋`void`
  promise 全部拆除，换成 DB lease＋心跳＋30 分钟超时。
- **Phase 只进不退**：`init → premise → outline → writing → complete`。
- **Flow 描述轮内活跃流程**：`writing / reviewing / rewriting / polishing / steering`，允许切换，
  反常跳转由代码轻量校验拦截（如 `rewriting → reviewing` 禁止）。
- **议会边界原则**（与 ainovel“拒绝复杂编排”和解）：多 Agent 讨论只允许存在于 Writer 工序的
  plan 与 check 两步之内，且步序/超时/fallback 全由确定性代码钉死。调度与裁决永不进议会。

## 2. 角色分工

- **Architect**：书名/简介/前提/大纲/角色档案/世界规则；滚动展开下一弧·卷（参考前文摘要＋角色快照）；
  失败出路的第一执行人（改谱/重排后续）。
- **Writer**：一章的构思/写作/自审/提交，工序固定（§3）。工序内含导演（plan）、演员（intent＋veto）、
  写手（draft）、三守卫（check）。
- **Editor**：弧级评审（结构＋审美）＋卷级评审；重写/打磨队列Owner；手改接纳（/sync）后补建摘要快照。
- **Arbiter**：单次调用、结果落盘可回放。仅三件事：启动选路、干预分诊、失败/僵局出路。
  用 default 模型，不开放独立配置。

## 3. Writer 固定工序（每章，顺序严格，步步 checkpoint）

1. `context` — 素材编译器组装（§8）：前情摘要、伏笔台账、角色状态、风格规则、相关章节推荐、
   下一章预告、本章功能/能量/槽位、withheld 清单。
2. `read_prev` — 回读上一章（找回语气节奏；首章跳过）。
3. `plan` — 导演立纲（章纲 JSON 槽位表＋人话理由，引用章法库牌）→ 演员交戏（意图 JSON＋可选 veto，
   演员互不可见，只对导演负责）→ 导演综合（改槽位＋书面裁决；未解决 issues→下一章 obligation）。
   beats 未过编剧会不得进 plan。
4. `draft` — 写手按章纲槽位写正文，**不许加戏**（新增人物/秘密/能力即人物守卫 error）。
5. `check` — 三守卫独立评审（设定/人物/节奏，见 §6）＋总编综合裁决。JSON 解析 brace-aware＋3 次重试；
   配额类错误（403/402/429）标 `failed:配额`（非 blocked，不锁下一轮）。
6. `commit` — 原子发布（章节＋Tick＋transition＋obligation 流转），落盘事实字段。
   修订循环：check→revise 最多 2 轮，修不好进 blocked（文案作者可读，附重规划/废弃/改谱入口）。

## 4. 章法库＋仿写画像（名著写法）

- 手工 12 张种子卡保下限（开章×4：行动/对话/异常日常/悬置信息；中段×4：纠葛收紧/信息分期/关系试探/
  代价加码；收束×4：决定/后果/反转/静水钩；首章四卡：立人/小困境/承诺预演/开账）。
  卡格式：手法名/出处/适用功能/适用能量/做法（3-5 句可执行指令）/反模式。平台级资产，版本化。
- `/simulate` 蒸馏管线管上限：参考文本入 `simulate/`，Architect 蒸馏画像，compact 注入各 Agent 上下文；
  只借鉴结构节奏钩子，不复制表达与设定；按内容指纹增量更新。
- 存放与世界内题材规则分离（平台通用 vs 世界定制）。

## 5. 节律谱（起承转合节奏谱，能量派生）

首弧谱例（6-10 章）：起(2级,3槽)→承×2(2级,3槽)→承转之间(3级,4槽)→转(4级,5槽；5级变天全弧限1章须在转位)→
承缓冲(2级,3槽)→合(3级,4槽；必须开新账）。

- 能量＝事件清单上限（1呼吸/2裂缝/3收紧/4爆发/5变天），由功能＋弧序位派生，导演最多微调一档＋书面理由。
- 节奏守卫四执法：燃错位打回；连燃打回（两 4 级＋之间至少一章 ≤2 级）；合章不开账打回；改谱不改章
  （谱版本化留痕，已发布不动）。
- 谱由 Architect 在弧展开时立，Editor 弧评审时复核。

## 6. 审稿（review-agent 裁决，废死分数）

- 废除每维≥70/平均≥80；通过＝零 critical/error＋deletionTestPassed＋确定性检查
  （点名越权/首章超员/分号流水账/withheld 违规）。七维分仅展示。
- 人物守卫执 hardBoundary；节奏守卫执 §5；设定守卫执知识越权。
- 总编综合沿用 `resolveProposal＋unresolvedIssueIds` 形状，未解决转 obligation（只呈现不自动改规划）。

## 7. Store、Checkpoint、恢复

- 每个工具成功后写 checkpoint；崩溃/重启按 `progress＋最近 checkpoint` 精确到 step 续跑
  （“第 N 章 draft 已落盘，请继续 check”）；checkpoint 幂等，重复派发安全。
- 文件写入 temp＋fsync＋rename 原子操作；DB 事务保持原子发布语义。
- `waitChapterRun` 加 30 分钟超时；running/queued 超 30 分钟无心跳视为孤儿，由 Engine 按 Route 重建，
  禁止永久 running。

## 8. 素材编译器＋自适应上下文＋相关推荐

- 统一素材编译器替代各处 `slice`：token 预算（material 总预算 12k 字符起）＋按契约相关度排序截断＋
  记录丢弃数。超 27k 上限是编译器 bug，不是模型问题。
- 三级摘要（章/弧/卷）＋滑窗最近章＋相关章节推荐（伏笔/出场/状态/关系四维反查）＋下一章预告（钩子衔接）。
- CJK token 估算按 runes×1.5，不低估中文。

## 9. 人在回路：验收闸、干预、同步、诊断

- **逐章验收**：`/review on` 后每章需放行（许可跟章节号绑定；重写/评审/结构维护不耗许可；
  崩溃不误耗）。默认自动推进。
- **实时干预**：写作中随时注入意见，Arbiter 分诊（改设定→Architect；重写→Editor 入队；规则→即时落盘），
  每次裁定落盘可回放。干预入口常驻，不再是第 5 步。
- **手动编排退役**：砍掉第二条产章路径（Tick 范围＋事件池自选）；历史事件重组需求走“干预＋review 闸”覆盖。
  UI 从五步向导改为“本轮卡片＋章节流＋世界底账（折叠）”；图谱降为证据抽屉。本期先改后端路由与状态，
  UI 改版紧随其后（同一阶段，不拆两期）。
- **/sync**：手改已发布正文按 SHA-256 识别，接纳后重建摘要/时间线/伏笔/关系/风格记忆；有未接纳修改时
  续写被门禁挡住。**/diag**：流程/质量/规划/上下文四维诊断＋脱敏导出。
- 一次性配置（建档、边界确认）沉底，不再占常驻导航。

## 10. 双驱动与遗产（架构决策 2026-09-11）

- 契约驱动唯一正统；`engine/orchestrator`＋12 系统降级为背景素材发生器（日常小事/关系漂移，
  origin=background，不进契约验收）；保留 `chat.ts` 引用；README 涌现叙事后续重写。
- 迁移锁死世界（`WORKFLOW_MIGRATION_REQUIRED` 且无 workflow_runs）：Engine 提供“废弃并重建”一键路径；
  blocked 文案全部作者可读化。

## 11. 预算（免费模型）

- 单轮约 14-18 次调用（§3 工序内并行：演员并发 3、守卫并发 3），墙钟约为现状 1.5-2 倍。
- 任一步配额错误标 `failed:配额`，可免费重试，不锁流水线。

## 12. 验收

1. 可靠性：blocked 轮占比下降；孤儿 run 清零；迁移锁死一键恢复。
2. aha-1：互斥目标同场产出谈判结果＋可见 trace（谁→要什么→付什么代价→守住哪条底线）。
3. aha-2：至少一次演员 veto 被接受改纲（需构造互斥测试世界验收）。
4. 节律：承章超标被打回≥1 次；合章开新账 100%。
5. 回退：aha 任一不达标→砍 veto/代言与 R2/R3，保留单写＋强审稿（§3 的子集）。

## 13. 分阶段与度量

- 第一阶段：§1-§12 全部（含 UI 改版、手动编排退役、背景过滤器）。
- 第二阶段（换模型后）：意图碰撞谈判、谱自动优化。
- 度量：blocked 占比、平均修订轮次、确定性问题检出率；谱版本化复盘。
